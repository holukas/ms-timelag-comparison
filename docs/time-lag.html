Time lag

This page covers the study variable: why the time lag is difficult to determine for N₂O and CH₄, the five versions compared, the settings each one was run with, and the PWB method used by the fifth.

Fluxes are computed several times from the same raw data, changing only how the time lag between the vertical wind component and each gas (N₂O, CH₄, H₂O) is determined. Each version is identified by a short code (e.g. QCL-3) used throughout the notebooks and figures: the prefix is the campaign (QCL, quantum cascade laser, 2021_1; LGR, Los Gatos Research, 2021_2) and the number is the time-lag version.

Why the lag is hard for N₂O and CH₄

For CO₂ and H₂O the cross-covariance between the gas and the vertical wind has a clear peak, and finding the lag is routine. N₂O and CH₄ fluxes are often small enough that the peak is comparable to the noise in the rest of the search window. The search then fails, in one of two ways that pull the flux in opposite directions.

The peak is found, but it is a noise peak. With a low signal-to-noise ratio, the largest absolute covariance in the window can sit anywhere. Picking it inflates the flux away from zero, the mirroring bias. This is the failure the narrow window and the constant lag are meant to prevent.

No peak is found. When the cross-covariance contains no usable peak, the maximisation returns the largest value available at the boundary of the search window, and the detected lags accumulate at its 0 s and 10 s limits. A large share of such values indicates a failed search rather than a long lag. The flux resulting from these periods is not an estimate of the mirroring bias, and it can fall below that of the other versions rather than above it.

Which one dominates depends on the gas, the season and the flux magnitude, so a comparison of lag settings has to be read per gas, not as one rule. The versions below differ mainly in which of the two failures they guard against.

The five versions

Four of the five versions start from one exploratory run, CM-W, and use its peak lag distribution to configure themselves; the fifth, PWB OPT, is independent of them.

How the five versions relate. CM-W (variant 1) is one wide covariance-maximisation run (Nemitz steps 1 to 3): it keeps its own lags and yields the distribution peak (nominal lag) and the distribution range. The peak is the default fallback for variants 2 and 3 and the fixed lag for variant 4; the range sets the narrow window for variant 3. PWB OPT (variant 5) is independent. Settings of each version

The same scheme of five versions is applied to each campaign and to each gas (N₂O, CH₄, H₂O). The versions differ only in how the lag is found. The method abbreviations (CM, CM\(_{CTR}\), PWB, PWB\(_{OPT}\)) follow Vitale et al. (2024): CM = covariance maximisation, subscript CTR = constrained (narrow window), PWB = pre-whitening with block-bootstrap, PWB\(_{OPT}\) = the optimised PWB lag (the S1/S2/S3 decision rule applied to the per-period PWB estimates).

Implementation status: all five versions (-1 through -5) are produced for both campaigns. For -5 (PWB) the lag is detected and removed from the raw data before the EddyPro run, so that run applies no lag compensation; its per-chunk time-lag summaries are kept alongside the fluxes. The lag applied (and reported in the figures) is the optimised PWB\(_{OPT}\) lag, not the raw per-period PWB mode.

Nominal lags and narrow windows

For each campaign and gas, the nominal lag is the value used as the default fallback (-2, -3) and as the fixed lag (-4); the narrow window is the search range for -3. Values are derived from the per-period lag analysis (provenance: the full 2012 to 2022 per-period lag table); only the two periods covering these campaigns are reproduced here.

Applicability of each version

1. CM-W (wide window, no default). The exploratory first pass. It searches the whole 0 to 10 s window every half-hour with no fallback, so its output reveals the lag distribution and its modal peak, which versions 2 to 4 build on. With nothing constraining the search, it is the most exposed to the covariance-maximisation (“mirroring”) bias for low signal-to-noise gases like N₂O: per half-hour the lag that maximises the absolute covariance is picked, inflating the flux away from zero. Covariance can be maximised against the scalar S of interest itself, or against an inert gas on the same analyzer (shared sampling line, so the lag is easier to detect), whose lag is then applied to S. It is intended for characterising the lag and configuring versions 2 to 4 rather than for the final flux. Its flux is an upper bound of the mirroring bias only where the lag distribution shows that the search succeeded in most periods; a distribution dominated by values at the window limits indicates the second failure mode, in which case the resulting budget can fall below that of the other versions.

2. CM-W + default. The same wide window, with a fallback to the nominal lag (the CM-W peak) whenever the search is unreliable. It provides a per-half-hour lag while protecting against clearly implausible detections, but it retains most of the mirroring bias, because the search range is unchanged.

3. CM-W CTR + default. The search is constrained to a narrow window around the peak, with the same fallback. The narrow window limits the mirroring bias while still allowing the lag to follow real variation within a known range. It is appropriate where the true lag is well constrained and reasonably stable, and is the recommended covariance-maximisation option.

4. Constant lag. A single fixed lag at the CM-W peak, applied to every half-hour. It removes the covariance-maximisation bias entirely and is appropriate where the lag is physically stable, for example in a steady closed-path setup. It ignores any real variation of the lag over time, so it is only as reliable as the assumption that the lag is constant over the period.

5. PWB OPT. Independent of covariance maximisation and robust to the mirroring bias. It is the reference method (Vitale et al. 2024) against which the covariance-maximisation versions are compared. It also searches a window (symmetric ±10 s, wider than the window used for covariance maximisation here), but its lags remain close to the physical lag instead of accumulating at the limits. Where no clear lag can be detected, the optimal lag of the closest preceding period is carried forward, following the S1/S2/S3 rule described below.

Recommendations

  • Run CM-W first, since its lag distribution configures versions 2 to 4. Before its flux is interpreted as a bias estimate, check how often its lags fall on the window limits: a large share indicates a failed search rather than a small or large bias.
  • For a covariance-maximisation flux, the constrained CM-W CTR is preferable to the wide-window versions, as the narrow window is what limits the bias.
  • Apply the constant lag only where the lag is stable over the whole period.
  • Use PWB OPT where a bias-resistant lag is required without manual tuning of a search window, and as the reference for the other versions.

The PWB method in detail

How PWB finds the lag

For reactive and trace gases such as N₂O and CH₄, the gas-wind cross-correlation is often too weak for conventional covariance-maximization (CM) to determine the time lag reliably. The *-5 versions instead use the Pre-Whitening with Block-bootstrap (PWB) method (Vitale et al., 2024), as implemented in diive. It works in two stages.

Pre-whitening. An AR(p) filter (order chosen by AIC) removes serial autocorrelation from each series before the cross-correlation function (CCF) is computed. Turbulent wind and trace-gas series are strongly autocorrelated, which broadens and distorts the CCF peak. Whitening the residuals sharpens the peak and gives a cleaner lag estimate.

Block-bootstrap. Instead of a single CCF over the whole averaging period, the method draws Nᵦ resampled series by moving-block resampling, where overlapping blocks of length L preserve local autocorrelation. It detects the peak lag in each resample and summarizes the resulting distribution by its mode (the lag estimate) and a 95% Highest Density Interval (HDI). A narrow HDI means resampling consistently finds the same lag, which is the method’s reliability criterion.

Sonic temperature (T_sonic) is required. Four CCF combinations are evaluated (scalar × W and scalar × T_sonic, each with a scalar, W, or T_sonic AR filter), and the combination with the strongest peak is selected. The T_sonic-based combinations often recover a cleaner lag for gases with a weak scalar × W signal.

PWB also uses a search window. It is symmetric over ±10 s (the lag_max_s default in diive, matching the broad window of the paper) and therefore wider than the 0 to 10 s window of the covariance-maximization versions. The distinguishing property of PWB is not the absence of a window but that its lags do not accumulate at the window limits. The runs reported here used Nᵦ = 99 bootstrap samples and a block length of 20 s.

PWB\(_{OPT}\): choosing the lag to apply

The per-period PWB mode is not the lag that gets applied. Vitale et al. (2024, Sect. 2.3) define an optimal lag, PWB\(_{OPT}\), through three steps applied to the periods in temporal order:

  • S1 a lag whose 95% HDI range is below 0.5 s is reliable and is taken as optimal.
  • S2 a lag with a wider HDI is still taken as optimal if it deviates by no more than 0.5 s from the optimal lag of the closest preceding period.
  • S3 everything else is unreliable and is replaced by that preceding optimal lag.

The carry-forward refers to the closest preceding period only, never to later ones. Both thresholds are the 0.5 s recommended in the paper, which is also the value used in these runs: in the summary tables {gas}_is_reliable changes exactly at an HDI range of 0.50 s.

Implementation. The RFlux package (v3.2.0) implements the detection only: its exported tlag_detection() works on a single averaging period and returns the PWB lag with its HDI bounds, along with the CM and PW variants. The S1/S2/S3 selection is described in the paper but is not in the package, so diive implements it (diive/flux/hires/lag_pwb.py, apply_pwbopt). diive adds one step of its own on top: periods before the first reliable detection have nothing to carry forward, and are filled by back-filling the first reliable lag, then the median of the raw detected lags, then a constant fallback.

Reference: Vitale D. et al. (2024), Environmental and Ecological Statistics 31, 219-244, doi:10.1007/s10651-024-00615-9. Chamau (CH-Cha) is one of the four sites in that study, so its published PWB results are directly comparable to the ones here.

Detect-and-remove workflow

The *-5_PWB versions are produced with diive’s detect-and-remove TUI, an end-to-end pipeline that detects and removes the lag in a single run. There is no longer a separate pre-rotation step or a separate apply step: rotation is done in memory, and the lag-corrected 30-minute files come straight out. Launch it with:

uv run diive-tlag-pwb-detect-remove-tui

The form sets the input and output paths, the wind (u, v, w) and sonic-temperature columns, the scalars (CH₄, N₂O), the PWB and chunking parameters, the raw-file format (skip-rows, header rows, separator, file glob), and the per-chunk output naming. Settings persist between sessions in ~/.diive/detect_remove_tui.yaml, so you enter them only once. The same pipeline runs headless as uv run diive-tlag-pwb-detect-remove.

Each long raw file (e.g. 6 h) is read once and processed in 30-minute chunks snapped to the wall-clock grid (:00 / :30), in two phases:

  1. Detect. For each chunk, the wind vector is double-rotated in memory (the rotated data are never written to disk), and PreWhiteningBootstrap runs on the rotated W, each scalar, and sonic temperature to estimate the lag per gas.
  2. PWBOPT. Once every chunk is detected, the PWBOPT decision rule (S1/S2/S3 carry-forward and gap-fill) is applied across the whole chunk sequence in temporal order to pick the best lag for each chunk. This replaces a spurious wide-HDI estimate with the neighboring optimal lag.
  3. Remove. Each scalar in the unrotated chunk is shifted back by the optimized lag, and the lag-corrected chunk is written as its own 30-minute file, with the original header rows and column order preserved.

Outputs land in the output directory: the lag-corrected 30-minute files, a summary table (1_lag_detection/detect_and_remove_tlag_summary.csv), optional overview plots, and a log.txt of the run.

The lag-corrected files then go through normal flux processing with EC time-lag maximization disabled, because the tube delay has already been corrected here.

Keep H₂O in the EddyPro settings. Even though the study only looks at the N₂O and CH₄ fluxes, water vapor must still be included in the run. The high-frequency spectral correction (here EddyPro’s Fratini method) is humidity dependent and uses the H₂O series to characterize the tube attenuation, so dropping H₂O changes the correction applied to N₂O and CH₄ and biases their fluxes low. This matters for a fair comparison: the *-5 runs should differ from the other versions only in how the N₂O and CH₄ lag is handled, not in whether H₂O is present. Only the N₂O and CH₄ lag is removed beforehand (that is the study variable); the H₂O lag is left in the raw data and compensated by EddyPro in the normal way, using the same constant H₂O lag as the other versions.
